# marps-engine

Navigation engine for a Mars astronaut's HUD. It computes the optimal route between points over the Deuteronilus Mensae terrain, evaluates slopes and hazards, and returns everything needed to draw the HUD. **It knows nothing about the frontend**: it connects to Unity, a web viewer or hardware through interfaces.

The project started as a prototype for the NASA Space Apps Challenge 2026 hackathon (*Interplanetary Survival Guide: Martian Map*).

Contract for frontends: [docs/CONTRACT.md](docs/CONTRACT.md).

## Structure

```
src/Marps.Engine/          Core (netstandard2.1, Unity-compatible)
  Geometry/                Points, bearings
  Terrain/                 Height and hazard map, loaded from disk
  Routing/                 A* with time cost, walking model, simplification
  Mission/                 Mission (steps), hazard zones
  Navigation/              NavigationEngine (per session), alerts, line of sight, DTOs
  Abstractions/            Interfaces: IAstronautSensor, IHudSink, ISpaceWeatherProvider, ITerrainProvider
tests/Marps.Engine.Tests/  152 unit and real-data tests
tools/Marps.DataImport/    TIFF → binaries read by the engine (run once)
tools/Marps.Harness/       HTTP server + web page for manual testing
context/                   Data (ignored by git). processed/ is generated by DataImport.
```

## Requirements

- .NET SDK 9 (tested with 9.0.320).
- Data in `context/`: `crop_1025.tif`, `hazards_1025.tif`, `mission.json`, `hazards.json`, `reference_routes.json`.

## Getting started

```bash
# 1. Convert the TIFFs to binaries (once)
dotnet run --project tools/Marps.DataImport -- context

# 2. Tests
dotnet test

# 3. Manual test web harness
dotnet run --project tools/Marps.Harness
# open http://localhost:5080
```

To use another data folder: set the `MARPS_DATA` environment variable to the folder that contains `processed/`.

## Trying it in the browser

At `http://localhost:5080`:

1. **Compute route**: pick a leg in *Mission leg*, press *Load leg* and then *Compute route*. You can set origin and destination by clicking the map (*Set origin* / *Set destination* modes).
2. **Full mission**: *Full mission* computes B→P1→P2→P3→P4→B and compares each leg with the reference planner (length ±10 %, time no more than 2 % above, slope ≤ 22°).
3. **Simulated helmet**: in *Move astronaut*, click the map; adjust the heading with the slider and press *Send and read HUD*. With *auto (1 Hz)* it updates by itself. *Simulate 25 m advance* walks toward the next target.
4. **HUD**: shows next target, distance and relative bearing, alerts, objectives, nearby hazards and layers.
5. Hovering over the map shows coordinates, slope and terrain type.

## Technical decisions

- **Cost = time in suit**, not distance. Model `t = 0.013937·d + 0.090788·ascent + 0.042108·descent` (min), fitted to the 5 legs in `reference_routes.json` (max error 0.11 min).
- **Hard slope limit**: measured between the two nodes of each step (1.95 m), not with 0.5 m sampling. This way the 23.7° point flagged in the reference data is not stepped on.
- **1025-node grid**, 1.953125 m cell (same as Unity). 8-neighbor A* with a binary heap and reused arrays.
- **Sessions**: the engine remembers completed steps and the cached route per astronaut. It recalculates only if the target changes, if requested, or if the astronaut moves more than 15 m away from the route.
- **Mission steps** in order. The pending step is completed if the travelled path since the last sample passes within 10 m of its point; later steps are completed only by proximity to the current position (so returning through the base does not credit it again).

## Validation

- Terrain: 1025×1025 heights between −3623.578 and −3481.388 m; hazard 2.3 % (>22°), 9.0 % (15–22°), 13.8 % (rough).
- Reference legs: with the same model and terrain, the reference route costs 9.18 / 18.00 / 18.40 / 15.38 / 26.30 min (published: 9.1 / 17.9 / 18.3 / 15.2 / 26.3). Our routes cost 2–3 % less on each leg; distance is 2–6 % higher because we optimize time.
- Full mission: 4769 m, 85.3 min (reference: 4600 m, 87 min).
- Compute time (Debug, .NET 9): first route per leg 30–200 ms; HUD updates with cached route: median 0.5 ms, p95 1 ms.

## Assumptions to validate

- Antenna height (3 m) and eye height (1.7 m): not in the data. They only affect signal alerts.
- Rough-zone penalty: 1× (no extra penalty).
- Time model: fitted to reference data, not to measurements in a suit.
- `pitchDeg` is not used yet.
- Space weather and SWIM/SHARAD/THEMIS layer providers: interface only, not implemented.
- Unity: the core is netstandard2.1, but it uses `System.Text.Json` (in Unity you must add the package or replace the serialization).
